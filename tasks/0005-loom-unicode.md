# Task 0005: `loom_unicode` tables and `cargo xtask gen-unicode`

## Context
Loom identifiers follow UAX #31: `(XID_Start | "_") XID_Continue*` (spec §2.5). Non-ASCII
whitespace outside comments and strings is an error that names the character (spec §2.2.2),
so the lexer needs the `White_Space` property. Rust's standard library doesn't expose
these properties, and our policy is zero dependencies (no `unicode-ident`). So we generate
compact tables from the Unicode Character Database (UCD) **version 17.0.0** into a new crate,
`compiler/loom_unicode`, with a std-only generator in `xtask`. The UCD data is licensed
Unicode-3.0, which `deny.toml` already allows. Read AGENTS.md first.

## Goal
`loom_unicode::is_xid_start`, `is_xid_continue` and `is_white_space` are exact for Unicode
17.0.0, are generated reproducibly by `cargo xtask gen-unicode`, and are fast for ASCII.

## Requirements
1. `compiler/loom_unicode/Cargo.toml` copies `compiler/loom_span/Cargo.toml` with the name
   changed and the description
   `"Generated Unicode tables (XID, White_Space) used by the lexer and name resolution."`.
   No dependencies.
2. Public API in `src/lib.rs` (exact names, each `#[must_use] pub fn …(c: char) -> bool`):
   `is_xid_start`, `is_xid_continue`, `is_white_space`. Also
   `pub const UNICODE_VERSION: (u8, u8, u8) = (17, 0, 0);`.
   - ASCII fast path: `is_xid_start` is `A–Z a–z` for ASCII (note: `_` is **not** XID_Start;
     the lexer handles `_` separately). `is_xid_continue` is `A–Z a–z 0–9 _` for ASCII.
   - Non-ASCII: binary search over a sorted `&[(u32, u32)]` table of inclusive ranges.
3. The tables live in `src/tables.rs`, which starts with the comment
   `// @generated by \`cargo xtask gen-unicode\` from UCD 17.0.0. Do not edit.` and contains
   `pub(crate) static XID_START: &[(u32, u32)]`, `XID_CONTINUE`, and `WHITE_SPACE`. Ranges are
   merged (adjacent ranges joined) and formatted so that `cargo fmt --check` passes as-is.
   Add `#[rustfmt::skip]` on the statics if needed.
4. `cargo xtask gen-unicode <UCD_DIR>` reads `<UCD_DIR>/DerivedCoreProperties.txt` (for
   `XID_Start`, `XID_Continue`) and `<UCD_DIR>/PropList.txt` (for `White_Space`) and writes
   `compiler/loom_unicode/src/tables.rs`. It must not download anything: xtask stays
   offline and std-only. Document in the module doc comment how to get the files:
   `https://www.unicode.org/Public/17.0.0/ucd/DerivedCoreProperties.txt` and
   `…/PropList.txt`. The generator checks that the files' header lines name version 17.0.0
   and fails otherwise. Running it twice produces byte-identical output.
   Put the parsing in pure functions (`&str` → ranges) with unit tests in
   `xtask/src/gen_unicode.rs` (`#[cfg(test)]`), covering single code points, `..` ranges,
   comments, and merging of adjacent ranges.
5. Download the two UCD files yourself (in your environment, not in code), run the
   generator, and commit the generated `tables.rs`. **Do not commit the UCD files.**
6. Tests in `compiler/loom_unicode/tests/properties.rs`:
   - Spot checks, as a table: `'a'`, `'Z'`, `'é'`, `'ß'`, `'λ'`, `'Ж'`, `'中'` are
     XID_Start; `'0'`, `'_'`, `'\u{0301}'` (combining acute) are XID_Continue but not
     XID_Start; `'-'`, `' '`, `'😀'`, `'$'` are neither; `'\u{00A0}'`, `'\u{2003}'`,
     `'\u{3000}'`, `'\u{2028}'`, `' '`, `'\t'`, `'\n'` are White_Space; `'a'` and `'\u{200B}'`
     (zero width space) are not.
   - Invariants over **all** `char`s: every XID_Start char is XID_Continue; every ASCII char
     agrees with the ASCII definitions in requirement 2.
   - Cross-check against `std`: for every `char` `c` with `c.is_alphabetic()`, check that
     `is_xid_start(c) || is_xid_continue(c)` holds, except for a small, documented
     allow-list, if any is needed (explain each entry). This guards against a broken table.
7. Doc comments on all public items. Standard library only. Clippy `pedantic` with
   `-D warnings`. No `unsafe`.
